# Lily Birthday Vault

A fully frontend birthday-present app with a white and green lily-of-the-valley theme.

The public `index.html` page now behaves like a folded birthday card. The recipient unfolds it, enters one **master password**, and sees visible memory presents. Hidden presents are found through the **Search your memory to find a present** button.

There is no backend. Encryption and decryption happen in the browser with Web Crypto.

## Architecture

- One master password unlocks the whole memory box.
- `resources.encrypted.json` stores public metadata:
  - present title
  - visible or hidden
  - media item types contained in the present
  - present size/color/style
  - encrypted inline payloads for text and song links
  - file paths and IVs for encrypted image/video payloads
- Image and video bytes are encrypted into separate `.vault` files under `resources/`.
- Song presents store encrypted `https://music.youtube.com/` links.
- Each present can contain any combination of text, image, video, and song items.
- Hidden presents require a secret phrase. Matching lowercases the phrase and removes whitespace before comparing it.
- Hidden phrases are saved twice: a public hash for lookup, and an encrypted copy so the builder can display the phrase again after resume.

## Files

- `index.html` - the public folded birthday card.
- `builder.html` - local browser-based encryption builder.
- `resources.encrypted.json` - public encrypted manifest used by the app.
- `resources/*.vault` - encrypted image/video files generated by the builder.
- `src/crypto.js` - Web Crypto PBKDF2 and AES-GCM helpers.
- `src/greetings.js` - multilingual short greetings and easter egg translations.
- `src/app.js` - public unlock and present flow.
- `src/builder.js` - builder workflow and download export.
- `src/styles.css` - folded card, present grid, and resource styling.

## Create Presents

1. Open `builder.html` in a modern browser.
2. Enter the master password.
3. Add presents. Each present can include any combination of text, image, video, and song.
4. Choose whether each present is **visible** or **hidden**.
5. For hidden presents, enter a **Hidden unlock phrase**.
6. Present size, color, wrapping style, and text font are randomized when the present is added. Adjust them only if you want to.
7. Use a high PBKDF2 iteration count. The default is intentionally slow.
8. Click **Build encrypted downloads**.
9. If your browser supports direct folder access, click **Save directly to folder** and choose the folder containing `index.html`.
10. Otherwise, download `resources.encrypted.json` and every generated `resources/<name>.vault` file.
11. Place `resources.encrypted.json` next to `index.html`.
12. Create a `resources/` folder and place the `.vault` files inside it.
13. Commit and publish with GitHub Pages.

Browsers sandbox local files. A fully frontend builder cannot silently write into the project directory in Safari/Firefox. Chromium-based browsers expose the File System Access API, so the builder enables **Save directly to folder** there; otherwise download links are the fallback.

Use the small eye button inside password fields to temporarily reveal a password.

## Resume Editing

The builder can resume from a previous `resources.encrypted.json`. If the manifest and `.vault` files are already sitting next to the app on the same site or local server, **Resume previous build** loads them directly from disk. If the files are not available from the current origin, you can still fall back to selecting the manifest and any missing `.vault` files manually.

Text and song links are recovered from the manifest; image/video bytes are recovered from matching `.vault` files when they are reachable.

Hidden unlock phrases cannot be revealed because only their hash is stored. When a resumed hidden present keeps its phrase field empty, the builder preserves the existing phrase hash. Type a new phrase only when you want to replace it.

## Change Master Password

The builder has a **Change master password** section. Select the existing manifest, enter the current and new master passwords, and select any existing `.vault` media files. Inline text/song payloads are re-encrypted from the manifest; image/video `.vault` files must be selected because browsers cannot read them from disk automatically.

For local preview, run a static server from this directory:

```sh
python3 -m http.server 8000
```

Then open `http://localhost:8000`.

## Security Notes

This is appropriate for a personal gift, not for high-stakes secret storage. Since the encrypted manifest and `.vault` files are public on GitHub Pages, attackers can run offline password guesses. Use a long master password. Increasing PBKDF2 iterations makes each guess slower.

Present metadata is intentionally public so visible presents can appear before their content is opened. Text, image bytes, video bytes, song URLs, and saved hidden phrases are encrypted. Hidden phrase hashes are public metadata too; they hide the phrase from casual viewing but should not be treated as high-security secrets.

Argon2id would be stronger because it is memory-hard, but PBKDF2 is built into browsers and keeps this project dependency-free.
